# 案例：把知识库用在真实场景

*同一套循环——设 goal → 收集 → 审查 → 沉淀 → 召回——落到具体的东西上。*

[理念](../concepts/philosophy.md)讲了为什么知识库是你在训练的模型。这一组案例把它落地：不是抽象的"知识管理"，而是**围绕一个具体目标，把一类持续产生的材料托管进来，让它随你一起成长**。

每个案例都遵循同一个骨架：

1. **设 goal** — 给这件事划一个边界（对抗熵增）。
2. **收集入 raw/** — 把持续产生的材料汇进来。
3. **审查沉淀 wiki/** — 在 goal 约束下留下值得留的。
4. **召回复用** — 需要时让 AI 带着这份上下文帮你。

| 案例 | 你在托管什么 | goal 长什么样 |
|------|------------|--------------|
| [托管你的研究](research.md) | 论文、实验、想法 | "推进某个研究问题" |
| [托管你的 GitHub](github.md) | 项目、提交、技术决策 | "把某项目做扎实 / 讲清楚" |
| [托管你的简历](resume.md) | 经历、成果、能力证据 | “拿下某类岗位” |
| [托管你的书籍](book.md) | 技术书章节、要点 | “吃透一个主题” |

### 维护案例

不是“托管你的 X”场景，而是 OKS 贡献者 / 维护者遇到的工程教训：

| 案例 | 讲什么 |
|------|--------|
| [文档与实现的一致性](maintenance.md) | SKILL.md 写了但代码里没有的命令，怎么发现 + 修 + design check |

{: .tip }
不用三个一起上。挑一个你**每天都在产生材料**的场景开始——那里反馈最快，循环最容易转起来。
