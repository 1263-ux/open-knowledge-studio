# 多模态 Raw 抽取生产化路线图

> 状态：第二阶段执行基线  
> 制定日期：2026-07-14  
> 前置成果：第一阶段已跑通“成熟提取器 → 统一 Raw 包 → 校验 → OKS 召回”

## 1. 第二阶段目标

第二阶段的目标不是宣称“解析现实世界所有信息”，而是把第一阶段原型升级为一个对明确支持范围负责的生产级多模态录入内核：

> 对受支持的来源提供可安装、可重复、可恢复、可观测、可审核的 Raw 抽取服务；提取成功有证据，提取不完整有告警，失败有原因和回退。

生产级的判断标准由稳定性和质量保证决定，而不是支持格式数量决定。

## 2. 产品边界

### 2.1 做

- 保持现有 `raw → drafts → wiki` 生命周期不变；
- 提供 Python Library + CLI 作为唯一解析内核；
- 为 Skill、飞书机器人、浏览器扩展和服务端 API 预留稳定调用接口；
- 建立提取器插件协议、质量路由和回退链；
- 建立任务状态、幂等、缓存、重试、超时和取消；
- 建立人工审核和修正记录协议；
- 建立安全的临时文件、Cookie/凭证和原始资产管理；
- 建立结构化日志、指标、错误分类和基准测试；
- 对受支持模态提供明确 SLO 和版本兼容策略。

### 2.2 暂不做

- 自动概念抽取、自动 Wiki 和知识图谱；
- 通用聊天 Agent；
- 自研 OCR、ASR、Embedding 或视觉模型；
- 自研向量数据库；
- 一开始就开发完整桌面端或 SaaS 前端；
- 未经授权绕过平台访问控制；
- 对未验收格式承诺生产支持。

## 3. 生产支持分级

### Tier A：第二阶段必须达到生产支持

| 来源 | 主提取器 | 必须保留的证据 |
|---|---|---|
| 本地视频 MP4/MKV/MOV | Watch + faster-whisper + RapidOCR | 时间戳、帧、OCR bbox、原文件哈希 |
| 公开 B 站/YouTube URL | Watch + yt-dlp | URL指纹、临时媒体哈希、字幕/ASR状态、帧 |
| 图片 PNG/JPEG/WEBP | RapidOCR | 原图、文字、置信度、bbox |
| 数字/扫描 PDF | 轻量探测 + MinerU | 页码、bbox、图片、公式/表格风险 |
| PPTX | MarkItDown + OOXML资产解析 | 幻灯片页码、原文件、媒体和引用状态 |

### Tier B：完成真实样本验证后进入支持

- DOCX；
- HTML和静态网页；
- MP3/WAV/M4A单人音频；
- XLSX/CSV表格；
- 手写图片和复杂图表的证据保留。

### Tier C：实验性支持

- 抖音、视频号及其他强登录态平台；
- 动态网页和公众号；
- 多说话人、重叠语音和强噪声音频；
- 复杂代码录屏的代码结构恢复；
- VLM视觉语义描述。

Tier C 默认不得在产品文案中标为稳定支持。

## 4. 目标架构

```text
CLI / Python API / Skill / External Adapter
                    │
                    ▼
             Intake Controller
          任务ID、幂等、权限、限额
                    │
                    ▼
              Source Inspector
       MIME、真实格式、模态、风险、大小
                    │
                    ▼
               Policy Router
       轻量优先、质量升级、回退链、预算
                    │
                    ▼
             Extractor Adapters
 Watch / RapidOCR / MinerU / MarkItDown / ...
                    │
                    ▼
              Raw Normalizer
 metadata + content + evidence + assets
                    │
                    ▼
               Quality Gate
 覆盖、断链、乱码、空正文、定位、抽样质量
              ┌─────┴─────┐
              ▼           ▼
          Review Queue   Failed Job
              │         原因/重试/回退
              ▼
        Human-approved Raw
              │
              ▼
      Existing OKS ingest / recall
```

所有产品入口必须调用同一内核，禁止飞书、CLI和未来Web服务各自维护一套解析逻辑。

## 5. 核心工程任务

### 5.1 稳定提取器协议

定义统一接口：

```python
class ExtractorAdapter:
    def probe(source, context) -> ProbeResult: ...
    def extract(source, workspace, options) -> ExtractorResult: ...
    def healthcheck() -> HealthReport: ...
    def version() -> str: ...
```

每个适配器必须声明：

- 支持的 MIME、扩展名和平台；
- 需要的可执行文件、模型和环境变量；
- 是否需要网络或登录态；
- 可输出的模态与定位类型；
- 超时、取消和清理能力；
- 可重试错误与永久错误；
- 版本和结果兼容性。

### 5.2 内容探测和质量路由

不能只按扩展名路由。至少增加：

- MIME和文件签名校验；
- PDF文本层、扫描页比例、公式/表格风险探测；
- 视频时长、音轨、字幕轨、分辨率和帧率探测；
- 图片尺寸、文字密度和OCR空结果判断；
- Office容器结构和媒体关系探测；
- URL平台、公开性、字幕可用性和登录需求探测。

路由示例：

```text
PDF → 原生文本轻量提取
    ├─ 质量合格 → 打包
    └─ 空正文/扫描/公式高风险 → MinerU
```

### 5.3 Raw Schema v0.2

在保持 v0.1 可读取的前提下增加：

- `job_id`、`attempt_id`和幂等键；
- 来源获取状态和访问方式；
- 每个模态的提取状态；
- coverage检查定义和计算依据；
- 错误分类、重试次数和回退链；
- 人工修正记录；
- 内容与资产的校验和清单；
- 提取器配置快照；
- 隐私等级和保留策略；
- schema迁移命令。

### 5.4 任务系统

每次抽取必须具有明确状态：

```text
queued → probing → acquiring → extracting → packaging
       → validating → pending_review → approved/rejected
       → failed/cancelled
```

必须支持：

- 同一来源幂等提交；
- 已完成结果缓存；
- 崩溃后的任务恢复；
- 指数退避重试；
- 单步骤超时；
- 用户取消；
- 临时目录清理；
- 大文件和并发资源限制；
- GPU/CPU任务隔离。

### 5.5 质量门

结构质量自动检查：

- 必需文件存在；
- JSON/JSONL合法；
- 资产引用无断链；
- 提取器输出和打包数量一致；
- 来源与资产哈希可验证；
- 时间戳、页码、bbox等定位覆盖；
- 正文非空且长度不过度异常；
- 乱码、重复和低置信度比例；
- 临时媒体已按策略清理。

内容质量通过固定样本和人工抽样评估：

- 清晰普通话ASR字符错误率；
- 截图OCR字符准确率和阅读顺序；
- PDF页覆盖、标题层级、公式和表格抽样；
- PPT页覆盖、图片映射率；
- 视频时间定位误差；
- 人工审核耗时。

准确率目标必须绑定样本集、语言、提取器版本和参考硬件，禁止脱离条件宣传一个总准确率。

### 5.6 人工审核协议

保持三层结果：

```text
extractor-output   原始提取器结果，不可变
content            机器整理的Raw阅读视图
verified           人工修正视图
```

修正记录至少包含：

- 修改前和修改后；
- 证据ID；
- 修改者；
- 时间；
- 修改原因；
- 原视频时间、页面或bbox；
- 是否允许进入正式Raw。

第二阶段先实现CLI或轻量本地审核页，不开发完整知识管理客户端。

### 5.7 安全与隐私

- Cookie和Token不得写入Raw、日志或Git；
- 使用系统凭证存储或短期环境注入；
- 临时媒体目录必须受控并可自动删除；
- 记录资产保留期限和删除结果；
- 默认本地处理私有文件；
- 使用云模型必须显式授权并记录数据去向；
- 防止路径穿越、压缩包炸弹和异常超大文件；
- 对外部URL实施协议、域名和下载大小限制；
- 日志自动脱敏本地路径、Cookie和查询参数。

### 5.8 可观测性

结构化日志字段：

- job/capture/attempt ID；
- source type和route；
- extractor/version；
- 阶段耗时；
- CPU/GPU/内存峰值；
- 输入与输出大小；
- evidence和asset数量；
- coverage状态；
- warning和error code；
- retry和fallback原因。

核心指标：

- 受支持输入任务成功率；
- partial/failed比例；
- 各提取器P50/P95耗时；
- 每分钟视频、每页PDF处理成本；
- OCR/ASR人工抽样质量；
- 断链资产数量；
- 人工审核平均耗时；
- 缓存命中率；
- 临时文件清理失败数。

## 6. 生产验收指标

在固定回归样本集和参考机器上，Beta验收至少满足：

| 指标 | 目标 |
|---|---|
| Tier A结构化任务成功率 | ≥ 95%，失败均有稳定错误码 |
| 幂等性 | 同一幂等键重复执行不产生重复Raw |
| 打包覆盖 | 提取器交付结果与Raw打包数量100%对账 |
| 资产完整性 | `validate`后断链资产为0 |
| 可追溯性 | 被召回证据100%能回到来源定位或原资产 |
| 崩溃恢复 | 进程重启后任务可恢复或明确失败 |
| 临时数据 | 到期临时文件可验证清理 |
| 回归测试 | 单元、集成、真实样本矩阵全部通过 |
| 人工审核 | 3分钟清晰口播的目标审核时间≤3分钟 |

ASR/OCR语义准确率在建立人工标注集后单独设定，不在没有基线的情况下承诺。

## 7. 执行里程碑

### M0：第一阶段封板与可复现环境（1周）

- 提交第一阶段代码和文档；
- 固定Python和工具版本；
- 增加环境健康检查；
- 整理安装、模型缓存和示例命令；
- 建立脱敏的小型回归fixtures；
- 记录参考机器配置和基准方法。

完成标准：新机器按文档可跑通图片和一个短视频样本。

### M1：适配器协议与任务状态（1–2周）

- 拆分当前单文件适配器；
- 实现adapter registry；
- 实现job manifest和状态机；
- 实现幂等、缓存、超时、取消、重试和清理；
- 保持现有CLI兼容。

完成标准：中途杀死任务后可恢复或明确失败，不产生半成品正式Raw。

### M2：质量路由与Schema v0.2（1–2周）

- MIME/内容探测；
- PDF轻量/重型动态路由；
- OCR空结果、乱码和重复检测；
- coverage规则配置化；
- v0.1到v0.2迁移；
- 质量分级A/B/C/D。

完成标准：同一命令可自动决定轻量提取、升级提取或人工回退。

### M3：人工审核最小产品（1–2周）

- 本地审核命令或轻量页面；
- 视频时间跳转、图片bbox和PDF页回查；
- ASR/OCR修正记录；
- approve/reject；
- 经审核后进入正式Raw。

完成标准：用户不需要直接编辑JSONL即可完成一次审核。

### M4：Tier A真实回归与安全加固（1–2周）

- 每种Tier A来源至少5个差异化真实样本；
- 故障注入：断网、磁盘满、模型缺失、超时、无字幕、损坏文件；
- Cookie/Token脱敏；
- 临时文件审计；
- 资源限制和并发测试；
- Windows主环境回归，补充Linux CI。

完成标准：达到生产验收表中的结构性指标。

### M5：Beta入口（1周）

- 发布稳定CLI和Python API；
- 接入一个真实入口，优先Claude Code Skill或飞书机器人；
- 收集失败样本和审核耗时；
- 只对Tier A能力作稳定承诺。

## 9. 第二阶段完成定义

第二阶段完成时，系统应能回答：

- 支持哪些输入，哪些只是实验性支持？
- 为什么为这个输入选择该提取器？
- 任务进行到哪一步，是否能取消或重试？
- 提取器交付了多少内容，Raw实际保存了多少？
- 哪些内容未经校对或可能丢失？
- 每条召回内容如何回到视频时间、PDF页面或图片区域？
- 临时视频、Cookie和私有文件如何保存与删除？
- 新机器能否按文档复现？
- 新版本是否破坏旧Raw包？

只有这些问题都有稳定答案，才能称为生产级多模态Raw抽取，而不只是“支持很多格式”的演示系统。
