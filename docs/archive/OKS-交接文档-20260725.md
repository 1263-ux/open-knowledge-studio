## 一、项目概述

Open Knowledge Studio（OKS）是一个文件级知识工程 CLI，核心闭环：

```
采集 → Raw Bundle → Agent 理解 → Candidate → 人工审核 → Wiki → 搜索/召回
```

在原 `open-agent-power/open-knowledge-studio` 基础上，合并 `oks-connector` 独立仓库，新增多模态提取引擎、飞书集成、Agent 技能体系和双语支持。

### 模块依赖（无循环）

```
raw_bundle_adapter.py
  ├── constants.py        (SCHEMA_VERSION, PLUGIN_VERSION)
  ├── _shared.py          (公共工具, 元数据工厂)
  ├── route.py            (来源路由)
  ├── digest.py           (摘要生成)
  ├── capability_check.py (能力检测)
  ├── i18n.py             (双语)
  ├── network.py          (HTTP探测)
  ├── validator.py        (Bundle校验)
  └── extractors/         (4个提取器, 惰性导入)
       └── 依赖: _shared + constants (不依赖 raw_bundle_adapter)
```

### 数据流

```
oks ingest <source>
  → cli.py: 能力预检 (_capability_already_installed)
  → raw_bundle_adapter.py: run_ingest()
    → route.py: route_plan() 匹配提取器
    → capability_check.py: 验证环境
    → subprocess [隔离venv] → extractors/*.py → Raw Bundle
      → digest.py: auto-generate digest.md + update raw/index.json

Agent 流程:
  → cat raw/index.json (扫清单)
  → cat raw/<bundle>/digest.md (看摘要)
  → 读 content.md (深入理解)
  → 写 drafts/{slug}.md (生成 Candidate)
  → 用户审核 → oks drafts promote → wiki/
  → oks search / recall (知识可用)
```

## 三、已实现能力

### 1. 多模态采集

| 输入 | 提取器 | 安装命令 | 输出 |
|---|---|---|---|
| YouTube/Bilibili/抖音 | watch | `oks capability install watch --yes` | 字幕 + ASR + 关键帧 + OCR |
| .mp4/.mkv/.mp3 本地 | watch | 同上 | Whisper ASR + 帧 OCR |
| .pdf | mineru | `oks capability install pdf --yes` | 布局+文本+公式+图片 |
| .pptx/.docx/.html/.txt | markitdown | `oks capability install document --yes` | Markdown + 内嵌媒体 |
| .png/.jpg/.webp | rapidocr | (随 watch 安装) | OCR + bbox 坐标 |

### 2. 提取档位

- **quick**：平台字幕优先，不跑本地模型（2秒出结果）
- **forensic**：字幕锚点帧 + Whisper ASR + OCR 完整证据（885条证据/视频）

### 3. 飞书集成

- `oks feishu setup`：自动创建 Base、28字段采集表、表单
- `oks feishu submit`：写入待处理记录
- `oks feishu run-once`：认领→采集→Raw→Candidate→飞书消息审核→Base回写

### 4. Agent 支持

- `raw/index.json`：全局采集清单
- `raw/<bundle>/digest.md`：500字摘要（标题/来源/模态/证据统计/警告）
- `.claude/skills/ingest/SKILL.md`：完整 Agent 操作指引

### 5. CLI 核心

- `oks init/search/recall/status/wiki/drafts/distill/lint/metrics`
- 路由诊断：`oks-connector route <source>`（含支持格式列表）
- 能力自检：`oks-connector check`（Python版本+模块导入验证）
- 中英双语：`OKS_LANG=zh|en`

### 6. 错误诊断

- 中文面板 + 完整 stderr 传播
- 能力未安装时给出精确安装命令
- 未知文件类型列出全部25种支持格式
- 解释器健康检查（启动+版本+模块导入）

## 四、Agent 体验评估

### Agent 如何与 OKS 交互

Agent（Claude Code）通过三层获取信息：

| 层 | 文件 | 大小 | Agent 读法 |
|---|---|---|---|
| 全局索引 | `raw/index.json` | ~200B/条 | 扫一眼知道有哪些采集 |
| 摘要 | `raw/<bundle>/digest.md` | ~500字 | 秒读，知道这条内容是什么 |
| 完整证据 | `content.md` + `evidence.jsonl` | 几十KB | 需要引用事实时才查阅 |

### 一次完整 Agent 会话的体验

```
Agent 被唤醒
  → cat raw/index.json                          ← 扫到 3 条新采集
  → cat raw/xxx/digest.md                       ← 500字了解每条
  → 挑一条有价值的，读 content.md                 ← 理解内容
  → 需要引用事实时，查 evidence.jsonl 对应编号     ← 精确溯源
  → 写 drafts/{slug}.md                         ← 用自己的话输出 Candidate
  → 用户审核（飞书消息或 CLI）                      ← 人类把关
  → oks drafts promote → Wiki                   ← 知识沉淀
  → oks search / recall → 下次可检索              ← 闭环
```

### 做得好的

- **digest 让 Agent 秒懂**：不用逐条读 evidence，500 字摘要包含标题、来源、模态、证据量、警告、人工核验建议
- **index.json 是导航**：Agent 不用 `ls raw/` 猜，结构化清单直接告诉它有什么
- **skill 文件是说明书**：`.claude/skills/ingest/SKILL.md` 告诉 Agent 每一步该做什么
- **evidence 引用可追溯**：Agent 说"根据 `watch-speech-000042`"时，人可以验证

### 还需改进的

- Agent 首次接触 OKS 时，需要额外引导才知道先读 skill 文件
- `oks search` 只搜 Wiki 不搜 Raw，Agent 需要在 draft→promote 之后才能检索到内容——中间有延迟
- 100+ 条采集后 `index.json` 会变大，需考虑分页
- 错误状态分类（partial/failed/skipped）Agent 还不够直观地理解

### 对比：有无 digest 层的区别

| | 无 digest | 有 digest |
|---|---|---|
| Agent 看 1 条采集 | 读 content.md (~79KB) | 读 digest.md (~500B) |
| Agent 看 10 条采集 | 逐个读 10 个目录 | 扫 index.json 挑感兴趣的 |
| Agent 引用事实 | 需要全文检索 | evidence编号直接定位 |

## 五、能力边界与限制

### 当前无法处理的

- 需登录/反爬/动态渲染的网页 → 须浏览器人工快照
- 付费墙/地域限制内容
- 实时视频流
- YouTube 中文字幕受IP限流影响（已配置 yt-dlp sleep/retry 缓解）

### 未充分测试

- forensic 模式仅测过2条视频
- PDF MinerU 全链路（CLI 路径已修，但因处理耗时未完整跑通）
- 飞书 `listen` 审核监听
- 干净机器首次安装全流程

## 六、优缺点评估

### 优点

- **单仓库一步安装**：不再需要 pipx inject
- **模块化**：主控制器 777 行，10 个独立模块，无循环依赖
- **组件化能力**：4 个提取器按需独立安装，不装不下载
- **Agent 友好**：digest + index + 9 个 skill 文件
- **错误可追踪**：中文面板 + 安装命令 + evidence 溯源
- **测试稳定**：48/48 通过

### 缺点

- 对普通用户不友好（需要知道能力安装、环境变量）
- 飞书 listen 未测
- 干净机器验证未做
- 模块拆分引入了惰性导入（`main()` 里 8 个 `from X import Y`），不够优雅
- 部分共享工具仍有重复（`normalize_ocr_text` 在 `_shared.py` 和 `watch.py` 中有不同实现）
