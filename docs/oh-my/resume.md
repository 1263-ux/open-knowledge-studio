# 托管你的简历

{: .important }
> **OKS 不是在你说“帮我写简历”时临时拼一页漂亮文案。** 它先把你长期讲过、提交过并审核过的经历留下来；当你真的想投递时，再结合目标岗位，找回相关材料，生成一份你能逐条确认的岗位版简历。

## 先积累，不急着投递

平时，你可能零散地告诉 Agent：做过什么项目、承担过哪一段工作、学过哪些技术、喜欢什么方向；也可能给过旧简历、作品、代码仓库或项目复盘。

OKS 不会把这些聊天直接当成“简历事实”。它会分别留下：

- **原始材料**：旧 Word、项目链接、对话与外部材料，方便回看；
- **可复用经历**：例如医疗知识问答、RAG、LangChain4j / OpenAI API、Docker 与 Java 后端基础；
- **尚待补证的能力**：例如线上指标、MCP / Tool Calling、评测、Trace 或复杂编排；
- **你的取舍**：哪些经历可以对外讲，哪些只用于内部判断，哪些说法你已确认或明确拒绝。

这一步的结果不是一份简历，而是一套你自己的、带边界的职业材料。下次对话不用再从“我大概做过……”开始。

## 真要投递时，发生什么

当你说：

> 我想投 Agent 应用开发岗位。请帮我找合适的岗位；针对其中一个岗位准备简历，但不要把我没做过的事写进去。

Agent 的正确动作是：

```text
先召回已审核的经历、偏好与过往取舍
→ 在得到授权后收集 / 阅读目标岗位要求
→ 将岗位要求与现有证据逐项对应
→ 提出本次岗位的 Candidate 简历表述与缺口
→ 你审核后，才用 Office 工作流生成 Word
```

这里有两类材料，不能混为一谈：

| 材料 | OKS 如何使用 |
| --- | --- |
| 你的长期经历与已确认判断 | 优先召回；它们是本次简历的可复用基础。 |
| 新找到的岗位要求 | 作为本次投递的外部来源，用来判断匹配与缺口；不会自动变成你的能力。 |

## 本次岗位的 Candidate

本例以 **Agent 应用开发** 为目标。结合这份真实 Word 中已有的项目和技能，Candidate 可以写成：

> **Agent 应用开发方向**：具备 Java / Spring Boot 后端基础，完成过基于 LangChain4j 与 OpenAI API 的医疗知识问答实践；接触 RAG、Embedding 与向量检索，并完成 Docker 化运行配置。希望继续在 Agent 工作流、知识库检索与 AI 应用工程化方向积累真实交付经验。

它不把“接触过”涂成“精通”，也不因为岗位里出现 MCP、Tool Calling、评测或 Trace，就把这些词填进你的技能栏。它们会留在“待补证据”里，成为下一段该做什么的清单。

## 人最后审核的是什么

你审核的不是 Agent 的措辞好不好听，而是这一次投递是否准确：

1. 这份岗位值不值得投；
2. 哪些经历需要突出，哪些可以删去；
3. Candidate 中每个关键表述是否有你的材料支撑；
4. 哪些能力必须保留为“下一步补齐”，不能提前写进简历；
5. 是否允许生成并导出这一版 Word。

## Office 只是最后一步

审核通过后，OKS 才将 Candidate、来源边界和岗位要求交给 Office 工作流，生成岗位版 Word。原 Word 保持不动；新版本只重组与本次岗位有关的表达。

## 下一次投递会更快，但不会更冒进

下一份岗位若偏 RAG / 知识库，Agent 可以先找回医疗问答实践、RAG、Embedding、向量检索、Docker 和后端基础；若岗位要求 MCP、工具调用或评测，系统会明确显示这些仍缺项目证据。

这就是“托管简历”的含义：**长期材料能在新机会出现时被找回，但每一次对外表述仍由你决定。**
