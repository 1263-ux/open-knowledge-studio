# 托管你的简历

{: .important }
> **状态：真实材料已对照公开岗位。** 这不是一份“AI 润色的万能简历”，而是把一份真实的 Java 后端与 RAG 学习实践材料，重新组织成 Agent 应用开发的候选表达。姓名、联系方式、学校、公司、地点、精确时间与薪资均已脱敏。

## 这份材料里原本有什么

目标岗位：**初级 / 校招 Agent 应用开发**。

原简历不是从零开始转行，它已经有三组和该岗位直接有关的材料：

### 1. 医疗知识问答与 RAG 实践

材料记录了以下实际工作：

- 集成 **LangChain4j** 和 **OpenAI API**，实现基础医疗问答；
- 用 **RAG** 做医疗知识检索与回答增强；
- 调研并实践 **Embedding、向量检索与医疗知识库构建**；
- 完成 **Docker 容器化部署**和运行环境配置。

这是一条真实的 Agent 应用起点：不是“我会用大模型”的空话，而是已经碰到检索、知识库、模型调用与部署这几个环节。

### 2. 后端与工程基础

原材料中的技术栈包括：**Java、Spring Boot、MyBatis Plus、MySQL、Redis、Maven、Git、Linux、Swagger / OpenAPI 与 Docker**。

另有一个 Spring Cloud 智能零售系统学习实践：参与服务拆分与模块协作、业务数据管理，以及 Docker 环境部署和服务运行维护。它不能直接证明大规模生产经验，但能证明做 Agent 应用时并非只会拼 Prompt。

### 3. 继续中的实践

材料还记录了省级大学生创新创业项目的技术成员经历：参与项目方案设计、功能设计和技术实现；个人关注方向是 Web 安全、AI Agent 与 AI 安全。

## Agent 给出的候选表达

基于上面的材料，候选简历不该写“精通多 Agent 平台”，而应写成以下可核对的方向：

> **Agent 应用开发方向**：具备 Java / Spring Boot 后端基础，完成过基于 LangChain4j 与 OpenAI API 的医疗知识问答实践；接触 RAG、Embedding 与向量检索，并完成 Docker 化运行配置。希望继续在 Agent 工作流、知识库检索与 AI 应用工程化方向积累真实交付经验。

它保留了原材料中的技术和项目，不把“接触 / 学习 / 实践”改写成“主导 / 精通 / 已规模化上线”。

## 对照岗位后，哪些能投，哪些还要补

| 岗位要求 | 这份材料里的真实依据 | 现在不能声称的能力 |
| --- | --- | --- |
| RAG 与知识库应用 | 医疗问答、RAG、Embedding、向量检索 | 线上效果、准确率、并发、成本 |
| Agent 应用后端 | Java、Spring Boot、OpenAI API、Docker | 成熟 Agent 平台或大规模线上运维 |
| 工程交付 | MySQL、Redis、Swagger / OpenAPI、Git、Docker | 完整可观测、回归与故障恢复体系 |
| Agent 工作流 | 有 Agent 工作流实践和持续学习方向 | MCP / Tool Calling 的实际交付、复杂规划编排 |

公开岗位除了 RAG，也开始要求工具调用、MCP、评测、Trace 和可观测能力。这里的正确做法不是把它们塞进技能栏，而是把它们变成下一条能展示证据的项目任务。

## 人需要审核的不是文笔，而是事实

在把候选表达用于投递前，审核者需要逐项确认：

1. 医疗问答项目到底实现了哪些链路，哪些只是调研；
2. RAG 的资料来源、切分、检索和回答增强是否有可展示的代码或截图；
3. Docker 部署是本地练习还是可复现的交付；
4. 省级项目中本人负责的模块、产出和协作边界；
5. 下一步是否补一个 MCP / Tool Calling + 评测 / Trace 的小型项目，形成新的可验证材料。

## 这张案例还不能证明什么

- 不证明已投递、获得面试或拿到 offer；
- 不证明候选人具备资深平台设计、高并发或复杂多 Agent 编排经验；
- 不把接触过的技术等同于独立交付过的生产能力；
- 不公开原始简历、身份信息或未经确认的项目细节。
