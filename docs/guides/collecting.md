# 收集 Raw 材料

> 把值得保留的资料收录到 OKS，建立可追溯的知识来源。

Raw 材料是知识的起点。这个阶段的核心是：**选择性收录**，而不是无脑囤积。

---

## 快速决策：该收录吗？

### ✅ 应该收集

**你真正看过/读过的资料**
- 看完的技术视频、文章、论文
- 读完的书籍章节
- 参与过的技术讨论

**未来可能需要追溯来源的信息**
- 技术选型的调研资料
- 重要决策的讨论记录
- 踩坑和解决方案

**包含具体数据和结论的内容**
- 成本数据、性能指标
- 对比分析、测评结果
- 明确的技术建议

### ❌ 不应该收集

**随手转发的链接**
- 没看过内容 = 制造噪音
- 收藏夹堆积症的根源

**纯娱乐内容**
- 除非你在研究这个领域
- 娱乐就娱乐，不要假装学习

**敏感信息**
- 密码、密钥、token
- 个人隐私、商业机密
- OKS 是本地文件，但备份安全也要考虑

## A/B/C 分级策略

入库时对资料分级，帮助后续决策：

| 等级 | 定义 | 处理策略 |
|------|------|---------|
| **A级** | 核心资料，必须完整保留 | 必审必晋升 |
| **B级** | 有价值，提取关键点即可 | 选择性晋升 |
| **C级** | 参考资料，保留索引 | 只保留 Raw |

**A 级示例**：
- 项目核心技术决策文档
- 关键技术的深度教程
- 重要会议记录

**B 级示例**：
- 技术博客、产品介绍
- 一般性技术讨论
- 参考案例

**C 级示例**：
- 快速浏览的文章
- 备用方案资料
- "可能有用"的链接

> **实践建议**：A 级必审必晋升，B 级选择性晋升，C 级可以只保留 Raw 不生成 Wiki。

## 收录流程

### 方式 1：对话式收录（推荐）

在知识库目录中对 Agent 说：

```
收录这篇文章/视频/PDF。保留来源证据，生成 Candidate 后停下来让我审核。
```

Agent 会自动：
1. 判断资料类型
2. 选择合适的 Provider
3. 提取内容和元数据
4. 生成 Draft Candidate

### 方式 2：命令行收录

```bash
# 准备工作区
oks ingest prepare <文件或URL>

# 查看生成的 Draft
oks drafts list
```

### 方式 3：视频收录示例

以 B 站视频为例：

```bash
# 1. 下载视频和元数据
yt-dlp <视频URL>

# 2. 提取音频
ffmpeg -i video.mp4 -vn audio.wav

# 3. 转写文字
faster-whisper audio.wav

# 4. Agent 生成 Draft
# 对话："分析这个转写结果，提取核心知识点"
```

**时间成本**：约 5-10 分钟（取决于视频长度）

## 常见问题

### Q: 如何批量处理历史资料？

❌ **不要一次性导入**
- 会生成大量 Draft
- 审核负担太重，容易放弃

✅ **分批处理**
1. 优先处理最近 3 个月的（记忆最清晰）
2. 旧资料可以只保留 Raw，不生成 Wiki
3. 用主题分批（这周 AI，下周数据库）

**时间安排**：
- 每周处理 5-10 份资料
- 3 个月处理 60-120 份
- 比一次性处理更可持续

### Q: 成本和性能如何？

**存储成本**：
- 视频转写：约 100KB/分钟（纯文本）
- Wiki 页面：约 2-5KB/页

**ASR 成本**（视频转写）：
- faster-whisper 本地运行：**免费**
- tiny 模型：快速，略有误差
- base/small 模型：准确，较慢
