# Raw 多模态提取基准：2026-07-14

> 目标：验证成熟开源提取器能否把真实世界素材转换为可追溯 Raw，而不是验证自动总结或 Wiki 生成。

## 1. 测试原则

- 使用成熟项目负责媒体获取、ASR、OCR、版面和公式识别；
- Open Knowledge Studio 只承担模态探测、路由、结果映射、质量报告和召回接入；
- 工具成功退出不等于质量合格；
- 不修饰机器结果，不把错误公式、OCR或ASR伪装成已确认事实；
- 本轮为纯技术样本，使用 `benchmark: true`、`human_context: omitted`。

原始产物保存在忽略目录 `.oks/benchmarks/20260714-multimodal-v01/`，不直接污染正式 `raw/`。

## 2. 采用的成熟组件

| 组件 | 本轮职责 | 结论 |
|---|---|---|
| Watch Skill 1.0.0 | URL/本地视频获取、音频、ASR、取帧、去重、OCR | 作为视频主提取器 |
| yt-dlp | B站公开URL媒体与元数据获取 | 可用；登录字幕需要Cookie |
| faster-whisper small | 带时间戳语音转写 | 可用；必须保留未校对状态 |
| RapidOCR | 截图与视频帧OCR | 可用；适合作为图片回退 |
| MinerU 3.4.4 | PDF/图片版面、OCR、公式和资产提取 | 作为复杂PDF主提取器 |
| MarkItDown 0.1.6 | PPT和轻量文档转Markdown | PPT文本基线好，复杂PDF不合格 |

## 3. 实测结果

### 3.1 数字数学PDF

- 输入：`高中数学公式大全.pdf`，7页；
- MarkItDown：2.86秒，但产生大量畸形表格，公式字体未正确恢复；
- MinerU：280.2秒（首次包含模型下载），产出620行Markdown、32张图片资产、712个行内数学分隔符和40个块公式分隔符；
- 结论：MinerU的结构和资产明显更完整，但仍有错符号，状态应为 `partial`，需要原页证据和人工核验。

### 3.2 扫描公式PDF

- 输入：`扫描公式.pdf`，13页，原有文本层严重乱码；
- MinerU OCR模式：135.6秒；
- 输出：650行Markdown、56个产物文件、16个Markdown图片引用、352个行内数学分隔符和62个块公式分隔符；
- 结论：可检索性显著改善，但矢量、上下标和复杂公式仍有错误。不能因“存在文本层”跳过OCR，也不能直接晋升Wiki。

### 3.3 PPT

- 输入：`影海拾光-省赛答辩终版-v2.pptx`，15页；
- MarkItDown：0.66秒，页边界和正文文本可用；
- 缺口：Markdown中的图片引用没有形成可移植资产包；
- 结论：轻量文本通道可用，Raw打包器必须另行复制图片并保留幻灯片页码。

### 3.4 独立截图

- 输入：2560×1600会议截图；
- MinerU：30.7秒，只把整页保存为一张图片，Markdown无正文；
- RapidOCR：5.2秒，识别88个文本框，核心正文基本可读；
- 结论：第一阶段独立图片直接进入RapidOCR。保留原图、坐标、文本和置信度，不能只保存拼接后的纯文本；复杂版面可在后续按需增加MinerU路由。

### 3.5 本地混合字幕视频

- 输入：`口播前半段无字幕，后半段有字幕.mp4`，239秒；
- Watch Skill：168.9秒；
- 输出：完整带时间戳ASR、12张证据帧、12帧OCR；
- 正确行为：视频中前后两遍重复口播均被保留，没有被自动合并或总结；
- 缺口：场景检测得到0个场景，回退到均匀采样；OCR存在少量错字。

### 3.6 B站公开URL

- 输入：`BV1C24y1e7Bn`，325秒音乐视频；
- Watch Skill + yt-dlp：26.4秒；
- 输出：标题、作者、时长、分辨率和1张去重证据帧；
- 字幕：未登录无法获取，本轮禁用Whisper，明确报告无转写；
- 结论：URL可以直接处理，不要求用户手工永久下载。提取器内部仍需取得临时媒体流或文件；处理完成后只长期保存必要Raw资产。无语音证据时不得生成伪转写。

## 4. 由实测确定的路由

```text
输入
  ├─ 视频URL → Watch Skill/yt-dlp
  │              ├─ 平台字幕可用 → 字幕
  │              ├─ 无字幕且有语音 → faster-whisper
  │              └─ 需要画面 → 去重帧 + RapidOCR
  ├─ 本地视频 → Watch Skill → ASR + 帧 + OCR
  ├─ 普通PPT/Office → MarkItDown → 文本 + 页/幻灯片定位 + 资产补包
  ├─ 数字/扫描/公式PDF → MinerU → Markdown + JSON + 页面/图片证据
  └─ 独立图片 → RapidOCR → OCR文字 + bbox + 原图证据
```

这不是按文件扩展名“一招鲜”，而是轻量优先、质量门控、必要时升级。

## 5. 当前质量门控

以下任一情况必须标记 `partial`：

- 字幕、ASR或OCR未经人工抽样；
- PDF含公式、手写、复杂表格或异常字体；
- 页面/时间戳/坐标覆盖不完整；
- 平台因登录态缺少字幕或元数据；
- Markdown引用的图片资产没有被打包；
- 提取器输出为空但原始文件显然包含信息。

正文为空时不得结束为成功，应触发下一路由或记录人工回退。

## 6. 当前判断

核心目标已经得到初步证明：现实视频、平台URL、PDF、PPT和图片可以通过成熟工具进入统一Raw候选层，且失败可以被明确暴露。

本轮已经完成MinerU输出的第一条薄适配：真实扫描PDF被映射为 `raw.md`、`metadata.json`、`evidence.jsonl`、`document.md`、`quality-report.json` 和48个图片资产。隔离的临时OKS根目录可以通过“质点运动学 位移矢量 速度”召回页码与坐标证据。

下一步不是继续自研ASR、OCR或视频下载器，而是为已选提取器增加同级薄适配，并把质量门控做成可重复命令。全程不改变现有 `raw → drafts → wiki` 主流程。

## 7. 候选项目对比实验

本轮继续用同一批真实素材测试 Docling 2.112.0 和 BiliNote（提交 `6d67e5a`）。候选项目只执行到提取中间层，不采用其摘要、问答、数据库或前端产品层。

### 7.1 Docling

- PPTX：15页答辩文件在8.4秒内导出约12 KB Markdown、212 KB JSON和17个图片资产；证明其结构化JSON和资产引用可作为适配参考。
- Windows路径：相对输出路径配合 `referenced` 图片模式会重复拼接目录并导出失败；改用绝对输出路径后成功。
- 中文质量：同一PPTX的正文出现系统性乱码，不能作为中文Office主提取器；MarkItDown在该样本上的中文正文更可靠。
- 数字PDF：默认 `docling_parse` 后端将7页文件判断为 `7!=-1` 并拒绝解析。
- PDF回退：切换 `pypdfium2` 后进入标准布局流水线，但首次模型下载在当前网络环境失败；Hugging Face镜像可列仓库文件，却无法满足模型文件元数据下载。该失败应归类为部署/模型获取失败，不应伪装成文件解析失败。
- 结论：暂不替换 MinerU 和 MarkItDown。保留为后续可选解析器，并借鉴其无损JSON、元素引用和资产模型；进入主路由前必须补充中文回归样本和离线模型包方案。

### 7.2 BiliNote

- 在线字幕：直接调用其B站 player API，对 `BV1Hu411s7J1`、`BV1TJxCzSEEZ?p=54` 和 `BV1C24y1e7Bn` 均能正确解析BV号、分P和cid，总耗时4.7秒。
- 字幕结果：三个样本在无Cookie状态下均无可用字幕轨，流程明确返回空结果；说明“平台字幕优先”值得复用，但仍需下载音轨并ASR回退。
- 本地画面：对142秒Java视频每6秒采样一次，2.02秒输出24帧，24帧全部保留。
- 去重缺陷：其实现只比较相邻JPEG文件的MD5；视频压缩导致视觉近似帧通常字节不同，因此不能替代场景检测、感知哈希或相似度去重。
- ASR：与现有路线一样使用 `faster-whisper`，没有必要为同一底层引擎重复下载模型并做一次无信息增益的速度对比。
- 结论：复用B站字幕API、分P识别、Cookie注入点和下载回退思路；不接入完整BiliNote服务，不采用其固定间隔关键帧和LLM笔记生成层。

### 7.3 最终组合

| 输入/能力 | 当前主实现 | 回退或候选 | 选择依据 |
|---|---|---|---|
| 平台字幕 | 平台接口；吸收BiliNote适配思路 | yt-dlp字幕 | 无字幕时显式进入ASR，不生成伪文本 |
| 本地/URL视频 | Watch Skill + yt-dlp | BiliNote平台下载适配 | Watch已同时验证时间戳ASR、证据帧和OCR |
| ASR | faster-whisper | 后续多说话人样本再评估WhisperX | 当前单人样本无需引入对齐和说话人依赖 |
| 视频帧 | 场景检测 + 相似度/感知去重 | 固定间隔仅作兜底 | BiliNote的MD5去重真实样本无效 |
| 复杂/扫描PDF | MinerU | Docling可选 | MinerU已在两类真实PDF成功；Docling冷启动失败 |
| 中文PPT/轻量Office | MarkItDown + 资产补包 | Docling可选 | 本轮Docling中文正文乱码 |
| 独立图片 | RapidOCR + 原图证据 | MinerU版面结果 | 当前优先稳定OCR与坐标；复杂版面再升级 |

当前不安装Agent Reach和WhisperX。前者属于跨平台获取层，后者属于多说话人/精确字级对齐路由；在对应真实缺口出现前接入只会扩大依赖面。

## 8. 第一版统一适配器验收

- 真实Java视频：142.5秒，Watch Skill端到端处理126.7秒；产出131段时间戳逐字稿、10张打包证据帧、208个带坐标OCR块和349条原子证据。
- 视频质量门：131/131段逐字稿、10/10帧、208/208个OCR块和349/349条证据均完成打包；状态为 `partial`，原因是逐字稿尚未人工校对且场景检测回退需要抽样确认。
- 真实PPT：保留15页正文证据、原始PPTX和32个内嵌媒体；17个无法与MarkItDown占位名可靠映射的图片引用被显式改写为未映射标记，原始提取Markdown另行保留。
- PPT质量门：15/15页正文证据和32/32个内嵌媒体完成打包；17个Markdown图片引用无法映射，因此覆盖状态为`partial`并进入warnings，而不是写死“零损失”。
- 两个Raw包均通过 `raw_bundle_adapter.py validate`。
- 隔离知识库执行 `oks recall "三元运算符"`，成功召回5条逐字稿证据，包括19.8–21.0秒和34.8–35.7秒的原始时间定位。

这证明第一版闭环已经成立：成熟提取器的真实中间结果可以经同一入口变成标准Raw包，并被现有召回引擎直接检索。

## 9. Raw可读层收敛

为避免普通用户直接面对数百条ASR/OCR原子证据，Raw包增加 `content.md`：

- 131个ASR原始片段按时间连续性和长度合并为7个可读段落；
- 每个段落保留首尾证据ID范围，可回到全部原始时间戳；
- 208个OCR框仍完整保存在 `evidence.jsonl`，可读层只展示每帧最多6行、500字符的OCR摘录；
- 10张证据帧继续保留，视觉内容没有被概念化或总结；
- 普通 `oks recall` 对多模态Raw包优先索引 `content.md`，正文未命中且名额未满时仅用OCR原子证据补位，不返回完整逐字稿或质量报告；
- 独立干净知识库召回“三元运算符”时，只返回 `raw/misc/java-video/content.md`。

该收敛只改变阅读视图，不删除底层证据，也不进入概念抽取阶段。

这里的`coverage_status=passed`只表示“成熟提取器已经交付的中间结果被Raw完整打包”，不表示OCR、ASR或公式语义正确，也不表示源视频所有时刻和画面都被覆盖。

URL包同时验证了指纹语义：链接字符串保存为`source_url_sha256`，提取器实际取得的临时媒体保存为独立`content_sha256`，状态为`verified`；临时媒体处理完成后可删除。
