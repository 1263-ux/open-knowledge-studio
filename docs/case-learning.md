# 托管你的学习

*把"我看过但记不清"变成"我能召回并解释"——围绕一个学习目标，让读过的资料沉淀成可复用的判断，而不是收藏夹里的一堆链接。*

学习的痛点不是找不到资料，而是**资料读完就散了**：教程看过三遍还是要重看，踩过的坑下次照踩，收藏夹越攒越焦虑。把学习当成一个 goal 驱动的知识库来托管，让它随你的理解一起长。

## 设 goal

- **学习 goal**：一个具体到能判断"学完没"的目标（如"能独立用 X 搭出 Y"），而不是"学习 X"。
- goal 决定边界。同一个技术栈有几百篇教程，goal 让你只沉淀**推进这个目标**的那部分。
- 目标达成后 goal 可以关掉，沉淀的知识留下来。

## 收集入 raw/

把学习过程中真实产生的材料汇入 `raw/`，**保真为先，不急着总结**：

- 官方文档、教程、博客 → `/ingest <URL>`，Agent 取证后落 `raw/`
- 视频课 → 装 `watch` 能力后摄入，字幕与关键帧都会留下
- 自己跑通的代码片段、报错与解法 → 记下来，**报错信息原样保留**
- 没懂的地方 → 也记，标明"哪里没懂"

{: .note }
> 摄入时 Agent 会做 A/B/C 分级：只有 A 级（有可复用结论且证据支持）才写成候选。B/C 只记判断与理由，**原始材料一律保留** —— 分级是意见，证据是记录。

## 审查沉淀 wiki/

`/promote` 审阅候选时，按三种类型分：

- **concept** — 你**真正理解透**的机制。判据很简单：能不看资料给别人讲明白
- **strategy** — 验证有效的做法、调试套路、选型判断
- **anti-pattern** — **踩过的坑**。召回时权重最高（×1.5），就是为了让你不再踩第二次

用[知识演化关系](frontmatter-schema.md)串起理解的变化：早期的错误理解被 `supersedes`，读到更深的资料后 `enriches`。**理解本身的演进过程会被完整留住。**

## 召回复用

```bash
oks recall "你要解决的具体问题"
```

- 重新上手一个久违的技术时，先召回自己当初的笔记与踩坑
- 运行 `oks hook install` 后，你向 Agent 提问时相关记忆会自动注入，不必手敲命令
- 写总结、做分享时，召回该主题下所有沉淀

{: .important }
> 学习最怕的是"重复劳动"：同一个坑踩两次、同一份文档读三遍。anti-pattern 的高权重与记忆曲线的联合作用，就是让**代价最高的经验最容易被想起**。

## 一份真实产出示例

[Kimi K3 深度分析](cases/kimi-k3-deep-analysis.md) 是这条链路跑完的真实产物：6 份官方资料经 `document` 提取器摄入 → Raw → Candidate → 人工审阅。

值得看的是它**如何标注自己的边界**：哪些声明可追溯到具体行号（`[verified]`）、哪些是工程推断（`[inferred]`）、提取器漏掉了什么（基准图表是图片，未转录）、以及哪些**根本没测**（未发起任何 API 调用）。

这正是"托管学习"与"收藏链接"的差别 —— **它诚实地说明了自己知道什么、不知道什么。**

## 第一步该做什么

1. 给当前在学的东西设一个能判断完成的 goal。
2. 把**最近读的一份**资料 `/ingest` 进来，审阅它给出的候选。
3. 把**最近踩的一个坑**记成 anti-pattern，然后召回一次试试。
