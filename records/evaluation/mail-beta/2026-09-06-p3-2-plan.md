# P3.2 — Long-task Beta and Host Alignment Plan

状态：已开始；协议冻结，先执行 BETA-07。

## Goal

验证 Mail 能否让 Agent B 在真实长任务中直接继续工作，而不是只完成一次
消息收发。每项任务都必须留下可检查的文件差异、测试/审查结果或明确决策。

## Constraints

- 不新增 Mail 字段、Thread 状态、ack 语义或 wake/lifecycle API。
- 不启用 daemon、heartbeat、WebSocket、Redis、MQ 或跨机器产品化服务。
- Agent 写入只允许发生在任务专用临时工作区；主工作区只接收评估记录。
- 一次只允许一个写入者；冲突任务使用两个临时 Session，但不并行写同一文件。
- 不把模型自述当证据；以 canonical message、receipt、diff、命令输出和宿主日志为准。

## Work packages

| ID | Route / host | Real task | Evidence required |
| --- | --- | --- | --- |
| BETA-07 | Human → Codex CLI | 在临时任务工作区完成一个有验收条件的文档修改，并回到原 Thread 报告 diff | wait/presented/ack、文件 diff、检查结果、same-Thread reply |
| BETA-08 | Codex → Claude interactive | Claude interactive 接收一项只读审查，确认 Hook/Session 行为并回复 | 真实 interactive 日志、receipt、ack/reply 状态；不采纳 headless 结论 |
| BETA-09 | Human → Agent | 真实研究/审查任务，要求 Agent 只用 Mail 中的上下文继续工作 | 结果文件或报告、`context_reask_count`、人工介入 |
| BETA-10 | Human → Codex Session A/B | 冲突任务暂停后由 Session B 接手，完成一次明确合并决策 | A/B receipts、单一最终决策、无重复工作 |
| BETA-11 | Codex ↔ Codex local Git mirror | 两个临时目录模拟跨机器 Git 同步，验证 Thread/receipt 与提交边界 | fetch/push 日志、并发提交结果、可回退说明；不接远端 |

## Execution order

1. BETA-07 先验证“Mail → Agent → 文件结果”，作为长任务基线。
2. BETA-08 单独验证 Claude interactive；若宿主阻断，记录失败分类，不改 Core。
3. BETA-09、BETA-10 补齐研究与跨 Session 冲突语义。
4. BETA-11 只在本地 bare Git mirror 上验证 Git-backed 协调，不发布、不推送外部。
5. 每个任务即时写任务卡；批次结束更新 Host 矩阵和聚合指标。

## Acceptance gates

- 至少 4/5 任务有明确结果证据，且失败不被归入“消息未送达”以外的错误类别。
- `context_reask_count`、`human_intervention_count`、`duplicate_work_count` 都有
  可追溯来源；未知值保持 `unknown`。
- Claude interactive 的状态必须与 Claude headless 分开记录。
- Git mirror 只证明文件同步和提交并发行为，不证明网络、daemon 或 wake 能力。
- 未累计 20--30 个真实失败事件前，不增加协议或生命周期设计。

## Rollback / stop rules

- 所有 Mail 和 Session 文件位于 `C:\Users\chenfeng\AppData\Local\Temp\oks-mail-p3-beta-*`。
- Agent 误写主工作区时立即停止该任务，保留 diff，回到 PLAN；不自动清理或覆盖用户改动。
- 同类逻辑失败连续两次，回到 PLAN/RETHINK；宿主权限、配额或网络失败单独标为
  `host_limitation`/环境阻塞，不通过协议补丁掩盖。
