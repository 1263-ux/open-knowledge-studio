# P3.3 — Failure Accumulation and Decision Gate

状态：RETHINK 门禁；已完成历史证据回填和 BETA-12--BETA-15，尚未达到扩展协议的决策阈值。

## Goal

把真实 Beta 中的失败从“印象”变成可追踪事件，区分 Mail Core、Host Adapter、
Agent 行为和操作失误。累计 20--30 个有证据的真实失败事件后，才决定是否需要
任何协议、生命周期或宿主能力变化。

## Constraints

- 不新增 Mail 字段、Thread 状态、ack 语义、任务 claim 或 wake API。
- 不引入 daemon、heartbeat、WebSocket、Redis、MQ 或跨机器产品化传输。
- 只纳入真实任务中的事件；人为构造的错误调用只能作为回归测试，不能计入阈值。
- 每个事件必须关联任务卡、canonical message、receipt、命令输出、宿主日志或结果文件。
- 一个根因记一个主事件；同一事件的表现症状写在备注，不重复计数。
- 保护现有 dirty worktree；新的 Agent 任务继续使用专用临时根。

## Failure admission rules

计入阈值的事件必须满足：真实任务正在执行、预期行为已写入任务卡、发生了可观察
偏差、且可由证据复核。`host_limitation` 和 `agent_ignored_mail` 可以计入，
因为它们直接影响协作闭环；纯命令拼写或测试用例故意触发的拒绝单独登记，不计入
协议决策阈值。

## Verification and stop rules

- 失败登记表每轮只追加，不改写历史判断；若证据不足写 `unknown`。
- 相同逻辑根因连续两次出现，停止继续试错，回到 PLAN/RETHINK。
- 宿主权限、配额、模型可用性或环境继承问题标记为 `host_limitation`，不通过
  Core 协议补丁掩盖。
- 发现主工作区被临时 Agent 写入时立即停止该任务并保留现场。
- 在阈值前不做 wake、调度、claim、重试租约或传输服务设计。
