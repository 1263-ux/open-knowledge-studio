# records — 过程记录

这里放**特定时间点的记录**，不是使用文档：

| 目录 | 内容 |
|---|---|
| `acceptance/` | 各版本的验收证据（场景、安全检查、产物索引） |
| `archive/` | 历史快照：PR 说明、交接文档、重构计划 |
| `research/` | 探索性研究笔记，讨论的方案可能并不存在于代码中 |
| `engineering-rounds-2-3.md` | v0.3.0 合并后那两轮工程加固的记录 |

## 为什么不放在 docs/

`docs/` 是 GitHub Pages 站点目录 —— Jekyll 会发布其下**每一个** `.md`。过程记录
放进去会以无标题条目出现在公开导航里，并随版本不断堆积。

用目录隔离而不是 `_config.yml` 的 `exclude` 清单：清单只是让文件不发布，文件仍在
站点目录里，下一个人照样往里加。

## 读这里的东西时

这些文档记录「当时怎么做、为什么这么做」，**不是当前口径**。里面的命令、路径、
目录结构、测试数量都可能已经过期。当前口径以
[`CONSTITUTION.md`](../CONSTITUTION.md) 与 [`docs/`](../docs/) 为准。

新增记录时：写进对应子目录，**不要**加 `title` / `nav_order` front matter（那是站点
页面才需要的），也不要从 `docs/` 的页面用相对路径链过来 —— 站点构建时这里不存在，
会成为死链。需要引用就用仓库 URL。
