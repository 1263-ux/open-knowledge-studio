# 文档优化指南

> 在现有文档基础上进行外科手术式优化，保留演进历史和宝贵经验

---

## 触发条件

当用户要求以下任何一项时使用此 Skill：
- "优化文档"
- "改进排版"
- "重构文档"
- "精简描述"
- "优化目录结构"

---

## 核心原则

### 1. Read First（先读后改）
- ✅ **必须**完整阅读原文档
- ✅ 理解文档上下文和演进历史
- ✅ 识别文档的核心价值
- ❌ 不要基于标题/前几行就开始修改

### 2. Understand History（理解历史）
- ✅ 用 `git log` 查看文档演进
- ✅ 理解为什么这样写（可能有深层原因）
- ✅ 保留经过多次迭代的宝贵经验
- ❌ 不要因为"看起来冗长"就删除

### 3. Incremental（渐进式改进）
- ✅ 一次只改 1-2 个文档
- ✅ 每次改进后让用户确认
- ✅ 小步快跑，避免大规模变动
- ❌ 不要一次性重构整个文档体系

### 4. Preserve Value（保留价值）
- ✅ 保留现有内容的核心信息
- ✅ 改进是"让内容更易读"，不是"重写内容"
- ✅ 优化排版 > 重写段落
- ❌ 不要删除技术细节（即使看起来冗长）

---

## 操作流程

### 阶段 1: 评估（必做）

```bash
# 1. 阅读原文档
Read <文档路径>

# 2. 查看演进历史
git log --oneline <文档路径> | head -10

# 3. 统计基本信息
wc -l <文档路径>
grep "^#" <文档路径>  # 查看标题结构
```

**输出评估报告**：
- 文档长度：XX 行
- 标题层级：是否清晰
- 主要问题：排版/结构/描述
- 核心价值：保留什么

### 阶段 2: 提案（征求同意）

**向用户提出 2-3 个具体改进点**：

```markdown
## 优化提案

基于阅读，我建议：

1. **排版优化**
   - 添加目录（TOC）
   - 用表格替代长段落（如：3 个地方）
   - 添加 Callout 突出重点（如：5 处警告）

2. **结构优化**
   - 调整标题层级（H3 → H2，2 处）
   - 添加章节分隔（3 个主要部分）

3. **描述精简**
   - 精简重复说明（如：XX 段落）
   - 通俗化技术术语（如：XX 概念）

**改动范围**：仅优化排版和措辞，不改变内容实质
**预计改动行数**：+30 / -15

是否同意执行？
```

### 阶段 3: 执行（获得同意后）

**优化技巧**：

#### A. 排版优化
- 添加目录（文档 > 150 行时）
- 用表格展示对比/列表
- 用 Callout 突出重点
- 代码块添加语言标记
- 合理使用空行分隔

#### B. 结构优化
- 清晰的标题层级（H1 → H2 → H3）
- 每个章节独立完整
- 添加"下一步"导航
- 相关链接集中放置

#### C. 描述精简
- 删除冗余的重复说明
- 技术术语通俗化（但保留准确性）
- 长句拆成短句
- 抽象概念配实例

**示例对比**：

❌ **优化前**（冗长）：
```markdown
在使用 OKS 进行知识管理的过程中，你需要注意的是，Draft 的审核是一个非常重要的环节，因为只有经过人工审核的内容才能晋升到 Wiki，而 Wiki 中的内容是可以被召回系统检索到的，所以审核质量直接影响召回效果。
```

✅ **优化后**（精简）：
```markdown
**Draft 审核很重要**：只有审核通过的内容才能进入 Wiki 并被召回。审核质量 = 召回质量。
```

### 阶段 4: 验证（改进后）

**检查清单**：
- [ ] 核心信息没有丢失
- [ ] 技术细节保持准确
- [ ] 链接和引用仍然有效
- [ ] 格式一致（frontmatter, markdown）

**让用户确认**：
```markdown
## 优化完成

已优化 <文档名>：
- 添加目录
- 3 处用表格替代段落
- 5 处添加 Callout
- 精简 2 段重复说明

**改动统计**：
- 原行数：711 行
- 新行数：685 行
- 删除：42 行（冗余说明）
- 新增：16 行（表格、Callout）

请查看效果，如需调整请告知。
```

## 禁止行为

### ❌ 大规模重构
- 不要拆分文件（除非用户明确要求）
- 不要创建新目录结构
- 不要改变导航体系

### ❌ 删除现有内容
- 不要删除技术细节
- 不要删除示例代码
- 不要删除历史演进说明
- 除非明确是"重复且冗余"

### ❌ 改变核心结构
- 不要改变文档的主要章节
- 不要改变信息的组织方式
- 不要改变术语定义

## 优化模板

### 模板 1: 添加目录（文档 > 150 行）

```markdown
## 快速导航

- [核心概念](#核心概念)
- [使用指南](#使用指南)
- [常见问题](#常见问题)

---
```

### 模板 2: 用表格替代段落

❌ **段落形式**：
```markdown
有 OKS 的情况下，知识来源是你看过的最新视频，成本数据是具体的 20元/次，可追溯性好...
```

✅ **表格形式**：
```markdown
| 维度 | 没有 OKS | 有 OKS |
|------|---------|--------|
| 知识来源 | AI 训练数据 | 你看过的最新视频 |
| 成本数据 | 模糊 | 具体（20元/次） |
| 可追溯性 | 无 | 完全可追溯 |
```

### 模板 3: Callout 突出重点

```markdown
> **注意**：Draft 审核是质量控制的关键环节。

> ⚠️ **警告**：不要在未审核的情况下直接晋升 Draft。

> 💡 **技巧**：用 A/B/C 分级策略管理大量 Draft。
```

## 实战示例

### 示例 1: best-practices.md 优化

**原问题**：711 行，太冗长

**优化方案**：
1. ✅ 添加目录（顶部）
2. ✅ 3 处用表格替代段落
3. ✅ 5 处添加 Callout
4. ✅ 精简 FAQ（7个 → 5个核心问题）
5. ❌ 不拆分文件

**预期效果**：685 行，可读性 +50%

### 示例 2: index.md 优化

**原问题**：导航不够清晰

**优化方案**：
1. ✅ 3 条路径用视觉分隔
2. ✅ 每条路径用表格展示
3. ✅ 添加 Callout 突出推荐路径
4. ❌ 不改变导航结构
